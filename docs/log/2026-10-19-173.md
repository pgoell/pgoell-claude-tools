workbench 1.3.0 (#173). `subagent-driven-development` runs the brief's verification commands in the main session before spec review, after `DONE` and after the fixes of `DONE_WITH_CONCERNS`; it no longer takes an agent's "passed" on its word. A failing command sends the task back as `DONE_WITH_CONCERNS`, and a second failure makes it `BLOCKED`. A brief with no verification command falls back to the slice's test commands, then the full relevant test set, then a question to the user, and the gap goes in the deviation list. Pilot's `claude-code-adapter.md` and task-list rule and `verification-before-completion`'s evidence table say the same. `reference/plugins/workbench.md` says so. No other page under `docs/` changed.
