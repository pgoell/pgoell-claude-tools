# 2026-10-19: Fix

workbench 1.4.12, issues #253 and #254, PR #255. A bounded task is a plan task that is not itself a slice. `writing-plans` gives it a shape in md: the heading `### Slice N: [task]`, keeping its place in the slice numbering as html keeps "Slice 0N", and a first line under the heading that starts with `**Ordering note:**`, says why the task sits there and names the slice it unblocks; in html the `p.order-note` comes first in its article, and the HTML plan template's sample note now names the slice it unblocks. A bounded task keeps every slice part: files, steps, test commands and acceptance criteria. The plan reviewer flags a bounded task whose ordering note is missing, not first, or names no slice it unblocks. `subagent-driven-development` finds the md note by that marker and says every rule for a slice holds for a bounded task too. `pilot` and its runtime references treat a bounded task as a unit like a slice: its own task-list item, verification and commit, and the `slices` gate pauses after it. Pages changed: `reference/plugins/workbench.md` and `how-to/move-to-workbench-pilot.md`, whose `slices` rows now name bounded tasks.
