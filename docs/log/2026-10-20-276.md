# 2026-10-20: Update

issue-loop 0.9.0, issue #276. A loop folder now holds its data and eight stubs (`next.sh`, `wait.sh`, `gate.sh`, `start.sh`, `notify.sh`, `grant.sh`, `takeover-check.sh`, `lib.sh`). Each stub runs the same script from the installed plugin, so a plugin update reaches every loop with no copying. The loop's own rule answers move from `rules.md` into `rules.local.md`, and `loop.env` gets `ISSUE_LOOP_VERSION` to pin or roll back a version. `scripts/upgrade.sh` brings an older folder up to the new shape: a dry run by default, then `--apply`. Pages changed: `reference/plugins/issue-loop.md`.
