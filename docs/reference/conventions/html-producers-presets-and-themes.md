# HTML producers, presets and themes

Read this before you change a skill that writes HTML, a producer template's CSS variables, a presentations preset or a diagram theme. Reasons and history: [html-producers-presets-and-themes](/explanation/html-producers-presets-and-themes.md).

- **HTML artifact output is a first-class skill mode.** A single-file HTML producer (`research:running-research`) ships an `## Output Format` section with the format and path resolution order, and a `references/<artifact>-template.html` whose `:root` block declares its own CSS variables. No shared design-system layer exists (it retired with `workbench` in 2026-10): a producer keeps its template's styles.
- **Multi-file HTML producers are a distinct shape.** Like `presentations:creating-presentations`: no `## Output Format` section, theming from presets, and the runtime shipped as `assets/`.
- **Artifact exporters are consumers, not producers.** Like `presentations:exporting-presentations-to-pptx`: no `## Output Format`; read tokens from the artifact (shared CSS, then inline `<style>`, which wins); output paths in its own SKILL.md; producer and exporter cross-reference each other in one sentence, and the exporter's description names the producer. `presentations:building-pptx-decks` writes no HTML: it consumes presets as Office theme colors, fonts and layouts, or fills a template a local preset keeps under `pptx/`, and it owns the PowerPoint tools (`assets/pptx_tool.py`, `assets/pptx_check.py`) the exporter also runs.
- **The presentations plugin themes through presets and parameterizes through `.pgoell/presentations/`.** Preset contract: `plugins/presentations/presets/README.md`. Bundled presets live in `presets/` (changing one is a version-bumped change); user-local ones in `.pgoell/presentations/presets/<name>/` of the consuming repo, never shipped. Resolution: prompt choice, then `.pgoell/presentations/config.md` `## Preset` (`Name:` local first then bundled; `Path:` any directory following the contract), then the single local preset (several: ask), then the bundled preset that fits the deck's use per the contract's table, stated with its reason (`default` otherwise). Copy the ten engine files from `creating-presentations/assets/` unmodified next to each deck: the deck scripts `deck-print.js`, `deck-controls.js`, `deck-thumbs.js`, `deck-edit.js`, `deck-rail.js`, `deck-stage.js`, `presenter.js` (load them in that order), and the presenter files `presenter.html`, `presenter-view.css`, `presenter-notes.js`. Check by hand: example slides link the preset's variable files and make no network requests; every text tier holds 4.5:1 contrast on every surface in both scopes; the dash rule covers `presets/`.
- **The diagrams plugin themes through its own theme contract, derived from presentations presets.** In `diagrams:creating-diagrams` colors come only from a `theme.css` with two `[data-theme]` blocks (contract `plugins/diagrams/themes/README.md`), bundled in `themes/` or user-local in `.pgoell/diagrams/themes/<name>/`. Selection: prompt, then `.pgoell/diagrams/config.md` `## Theme`, then an offer to derive from a configured presentations preset, then `classic`. Derive brand themes from preset tokens or a PPTX `theme1.xml`, never by hand. The fallback template's `THEME:START`/`THEME:END` block is a synced copy of `themes/classic/theme.css`: edit both together. The engine is archify at `1bb61c6` with changes listed in `plugins/diagrams/NOTICE`; a re-port reapplies them, the brand-mark removals and the dash substitution, then runs upstream's tests.
