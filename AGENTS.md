# pgoell-claude-tools

A plugin marketplace containing shared skills for Claude Code, Codex, and Cursor.

Claude Code, Codex, and Cursor use separate plugin metadata, but they must reuse the same skill directories. Do not duplicate `SKILL.md` files for another runtime. The Cursor metadata is generated from the other two; never edit it by hand (see the "Cursor manifests are generated" Design Decision).

Each Design Decision below states the rule only. Its reasons and history live in `docs/explanation/`; read them before changing a rule, not to follow one. Rules for one kind of task live in `docs/reference/conventions/`; "Task-specific rules" below says when to read each page.

## Repository Structure

```
AGENTS.md                   # Shared host-agent instructions (canonical file)
CLAUDE.md                   # Symlink to AGENTS.md; keep it a symlink, never write it
.claude-plugin/
  marketplace.json          # Claude Code plugin registry (name, source, version per plugin)
.agents/
  plugins/
    marketplace.json        # Codex plugin registry (local source, policy metadata, interface)
.cursor-plugin/
  marketplace.json          # Cursor registry, generated by `mise run sync-cursor-manifests`
.github/
  cursor-validate/          # Cursor's validator and schemas, vendored from cursor/plugins (MIT,
                            #   pinned commit in NOTICE), run by the validate-cursor-plugins job
plugins/
  <plugin-name>/
    .claude-plugin/
      plugin.json           # Claude Code plugin metadata
    .codex-plugin/
      plugin.json           # Codex metadata; must set "skills": "./skills/" unless the plugin
                            #   ships no skills (prose-styles, guards, session-title carry it
                            #   only to satisfy the version check)
    .cursor-plugin/
      plugin.json           # Generated by `mise run sync-cursor-manifests`, never hand-edited;
                            #   absent for plugins not offered in Cursor (deprecated,
                            #   prose-styles, guards, session-title, issue-loop)
    agents/                 # Reserved slot, unused by every plugin (see skill-design-patterns
                            #   in docs/reference/conventions/)
    hooks/                  # Optional: hook scripts plus hooks.json (Claude Code format); a
                            #   Cursor-format hooks-cursor.json beside it when the plugin ships
                            #   hooks to Cursor (workbench only)
    output-styles/          # Optional: Claude Code output styles, auto-loaded, namespaced
      <style>.md            #   <plugin>:<name>; frontmatter name, description,
                            #   keep-coding-instructions. No Codex equivalent. prose-styles only.
    presets/                # Optional: brand presets (presentations only); contract in
                            #   presets/README.md. User-local presets live in the consuming
                            #   project under .pgoell/presentations/, never in this repo.
    themes/                 # Optional: diagram themes (diagrams only); contract in
                            #   themes/README.md. User-local: .pgoell/diagrams/themes/.
    skills/
      <service>/
        SKILL.md            # Shared skill definition, used by Claude Code, Codex and Cursor
        engine/             # Optional shipped code driven by exact commands (diagrams only)
        <reference>.md      # Flat reference doc (legacy layout)
        references/         # Subdirectory layout (preferred for new skills)
          <reference>.md
    references/             # Optional plugin-level research notes or scaffolding, valid in a
                            #   stub and after skills ship. plugins/databricks/references/research/
                            #   is gitignored and local-only: never force-add it.
    tests/                  # Optional self-contained check of shipped scripts, run by hand
                            #   (issue-loop, insights, news, agent-system-management, file-size:
                            #   tests/run.sh with fakes or fixtures, no network;
                            #   presentations: tests/run.sh drives deck fixtures in headless Chrome;
                            #   atlassian: tests/run.sh parses the JSON bodies of its examples)
    LICENSE                 # Required for ported plugins (see port attribution rules)
    NOTICE                  # Required for ported plugins: per-file upstream attribution
    README.md               # Required for ported plugins: overview with a Credits section
docs/                       # User docs: a Diátaxis tree in OKF v0.2 (see ## Documentation)
  index.md                  # Documentation home, carries okf_version; read it first
  log.md                    # How the change log works; lists no entries
  log/YYYY-MM-DD-<slug>.md  # One file per change to the docs bundle
  tutorials/  how-to/  reference/  explanation/   # One folder per Diátaxis type
  reference/plugins/<name>.md   # One page per marketplace entry, plus index.md
mise-tasks/                 # Repo tasks; check-file-size runs the file-size plugin's script
.file-size-excludes         # This repo's excludes for that check
dotclaude/                  # Versioned global ~/.claude/CLAUDE.md (symlinked into place); not a plugin
containers/dev/             # Podman-first dev container (run-dev, egress proxy, README checklist)
```

## How to Develop a New Skill

Before you add a skill or plugin, read [docs/reference/conventions/developing-a-skill.md](docs/reference/conventions/developing-a-skill.md): the five steps, the manifest and SKILL.md templates, the docs sites a new plugin or skill updates, and "Skills may ship code". A new `SKILL.md` starts under the file-size limit (see "CI Checks"); step detail goes to `references/`, linked from the step that needs it.

## Documentation

User docs live in `docs/`, a Diátaxis tree in Open Knowledge Format v0.2. Read `docs/index.md` first.

- Every page except `index.md`, `log.md` and `log/*.md` starts with YAML frontmatter: `type`, `title`, `description`, `tags` (a list), `status`. `type` matches the folder: `Tutorial` (`tutorials/`), `How-to Guide` (`how-to/`), `Reference` (`reference/`), `Explanation` (`explanation/`). Quote a value that holds a colon-space.
- Folder `index.md` pages carry no frontmatter: an H1, one short paragraph, a bullet list of pages with one-line descriptions.
- Links between docs pages are bundle-relative (`/reference/plugins/workbench.md`); links out of `docs/` are relative paths (`../../plugins/workbench/README.md`).
- A new or changed page updates its folder's `index.md` and adds a new file under `docs/log/`, as `docs/log.md` says.
- Skill rows: this repo's plugins go in `docs/reference/skills.md`, external git-URL plugins in `docs/reference/upstream-skills.md`.
- No AI attribution on any page. The dash lint covers `docs/`: `grep -rnP '[\x{2014}\x{2013}]' docs/` must print nothing.
- Docs describe the code as it is now. A PR that makes a page wrong fixes it in the same PR.
- `mise run check-docs` link-checks `docs/` rooted at `docs/` and spell-checks it with the rest of the repo.

## CI Checks

`.github/workflows/pr-validation.yml` runs six checks on every PR against `master` (backed by `mise`, `lefthook`, and `mise-tasks/*`, also run locally on commit and push): formatting, JSON lint and file size, Conventional Commits, plugin version-bump lockstep, manifest schema validation (also fails when generated Cursor manifests drift or a `SKILL.md` sets `disable-model-invocation: true`), docs links and spelling over `README.md`, `AGENTS.md`, `plugins/` and `docs/` (also fails when a backticked prompt file name, `*-prompt.md` or `agents/*.md`, has no tracked file), and Cursor plugin validation. At pilot "Step 8: CI loop", `gh pr view <pr> --json statusCheckRollup` returns these six jobs, not an empty array.

- **File size.** No authored file passes 5000 tokens (bytes/4). `mise-tasks/check-file-size` runs the file-size plugin's script on staged files on commit and on every tracked file in `mise run lint` (pre-push and the CI lint job). This repo's excludes (generated, ported, frozen) are in `.file-size-excludes`; the defaults (lockfiles, binaries, license texts) are in the script. Split an over-limit file along a deep module (Ousterhout: a small interface over much hidden work), never by line count or into pass-through wrappers.
- Lefthook hooks run only where `lefthook install` ran (check `ls .git/hooks`; only sample files means nothing runs). So run `dprint fmt` on every markdown or JSON file you touched, plus the manual greps below, before committing.
- Run `dprint check` bare from the repo root; a path argument makes it find no files.
- `.workbench/` is gitignored but `.workbench/pilot.md` stays force-tracked: stage it with `git add -f .workbench/pilot.md`.
- Nothing tests skill behavior; until evals (see `agent-system-management:creating-skills`) cover a skill, check it by hand. The manual greps (dash lint, frontmatter YAML, invocation syntax) are the only structural gates.

## Design Decisions

### Versions and lockstep ([versions-and-lockstep](docs/explanation/versions-and-lockstep.md))

- **Every plugin change bumps version.** Any change to a plugin's skills, metadata, docs, hooks, agents, or tests bumps its version. New skills are minor; fixes, docs, tests, and description changes are patch unless they change behavior materially. Bump every site in lockstep: (1) `.claude-plugin/plugin.json`, only when it already declares `version` (`atlassian` and `google-workspace` omit it on purpose, because Claude Code reads their version from the marketplace entry); (2) `.codex-plugin/plugin.json`, always; (3) the plugin's `version` in `.claude-plugin/marketplace.json`; (4) the plugin's line in "Current Plugins" in this file. `.cursor-plugin/plugin.json` also holds the version, but `mise run sync-cursor-manifests` writes it from sites 1 to 3: run the task, never edit the file. `.agents/plugins/marketplace.json` holds no version. The bump is per PR, not per commit (with `Squash: yes` in `.workbench/pilot.md` a branch merges as one commit), so a branch that already bumped does not bump again; check with `git diff <base>..HEAD -- plugins/<plugin>/.claude-plugin/plugin.json plugins/<plugin>/.codex-plugin/plugin.json .claude-plugin/marketplace.json AGENTS.md`. Before picking the number, check open PRs and `git worktree list` (and each worktree's uncommitted diff) for a parallel branch bumping the same plugin; whichever ships second bumps again before merge. CI checks sites 1 to 3 and the Cursor manifest; site 4 is not checked, so it is on you.

### Runtimes and manifests ([shared-skills](docs/explanation/shared-skills.md))

- **Codex compatibility is metadata plus platform mapping.** Codex manifests sit beside Claude Code manifests and point at the same `skills` folder. Runtime tool differences go into the shared skill body as a mapping, never into duplicated skill files.
- **Cursor manifests are generated, not written.** `mise run sync-cursor-manifests` builds `.cursor-plugin/marketplace.json` and each `plugins/<name>/.cursor-plugin/plugin.json`; never hand-edit them. From `.claude-plugin/plugin.json`: `name`, `description`, `author`, `license`, `keywords`, `version` (the Codex version when Claude omits it). From the Codex manifest: `displayName` (from `interface`) and `skills` (when set). Plus `homepage` and `repository`. Cursor's schema rejects unknown fields, so add a field to the generator only when `plugin.schema.json` lists it. Cursor-only fields go in the task's `extra_for` function; its one use is workbench's `"hooks": "./hooks/hooks-cursor.json"` (Cursor would otherwise read the Claude Code `hooks/hooks.json`). The `EXCLUDE` list: `deprecated` (frozen archive), `prose-styles` (no Cursor output styles), `guards` (hook needs a `beforeShellExecution` port), `session-title` (sets a Claude Code title), `issue-loop` (drives Claude Code). Upstream-URL entries are skipped (no local folder). Run the task after any manifest change; `validate-plugin-schema` runs it with `--check` and fails on drift, and the `validate-cursor-plugins` job runs Cursor's validator from `.github/cursor-validate/`.
- **A plugin with skills may be registered for Claude Code only when its skills drive Claude Code itself** (`issue-loop`). Keep its `.codex-plugin/plugin.json` with `"skills": "./skills/"`, leave it out of `.agents/plugins/marketplace.json`, and say why in `docs/reference/runtimes.md`. A skill that only names Claude Code tools gets a platform mapping instead. issue-loop's files name the example project (Blattomat) for numbers and faults only; never names of people, hosts, accounts or data paths.

### Repository conventions ([repo-conventions](docs/explanation/repo-conventions.md))

- **Skills are self-contained.** A SKILL.md holds everything the agent needs to use the service, except reference docs it links to.
- **Skill invocation syntax in docs is `/<plugin>:<skill>`, not `/<marketplace>:<skill>`.** Always use the fully qualified form (`/atlassian:jira`); never teach the short `/<skill>` form. `pgoell-claude-tools` appears only in `/plugin install <plugin>@pgoell-claude-tools` and `codex plugin marketplace add pgoell/pgoell-claude-tools`. Audit: `grep -rnE '/pgoell-claude-tools:[a-z]' README.md docs/` must print nothing; `grep -rnE '/(atlassian|google-workspace|research|writing|runtime-bridge|agent-system-management|workbench|terminal|playground|databricks|learning|critique|presentations|diagrams|news|insights|file-size|issue-loop|ponytail|emil|vercel|taste-skill|deprecated):' docs/` should match each plugin whose skills the doc names. Keep that list to the plugins with skills in `.claude-plugin/marketplace.json`.
- **Em-dash lint and instruction text.** U+2014 and U+2013 are forbidden in every file: skills, `references/*.html`, vendored CSS and JS, root docs. In markdown, name them by codepoint, never as literals. Repo-wide check: `grep -rnP '[\x{2014}\x{2013}]' plugins/ README.md AGENTS.md`. It is not empty: 7 older tracked files (google-workspace recipes, workbench's visualizing-options, the frozen using-superpowers snapshot, session-start hook) are accepted debt, plus gitignored databricks research notes. So gate on changed files: `git diff <base>..HEAD --name-only | xargs grep -nP '[\x{2014}\x{2013}]'` must print nothing, and `README.md` and `AGENTS.md` stay clean. HTML body copy may use `&mdash;`, `&#8212;`, `&ndash;`, `&#8211;`. CSS and JS comments have no escape: substitute the character at port time.
- **SKILL.md frontmatter `description:` must not contain a colon-space unless the whole value is quoted.** Frontmatter must be strict YAML; an unquoted colon-space fails with `mapping values are not allowed here`. Rephrase (`Examples:` becomes `For example`) or quote the whole value. Validate by hand: feed the frontmatter to `python3 -c 'import yaml,sys; yaml.safe_load(sys.stdin)'`.
- **Lazy auth, never print secrets.** Never check auth up front: run the operation and diagnose auth failures in Self-Healing. Never print or echo credentials, tokens, or API keys; only test whether they are set (`test -n`).

### Skill design patterns ([skill-design-patterns](docs/explanation/skill-design-patterns.md))

- **Every skill is model-invocable.** No skill in this repo sets `disable-model-invocation` or ships an `agents/openai.yaml` with `allow_implicit_invocation: false` (the user's wish, 2026-10-19); `validate-plugin-schema` fails on the flag. Every description stays under about 100 words (500 characters). Upstream entries (`emil`) are outside this rule.
